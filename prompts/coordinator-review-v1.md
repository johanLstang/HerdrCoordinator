# Coordinator epic review policy v1

Use only the registered Coordinator review services for the configured project.
An epic handoff means ready for final review; it is not approval or main delivery.
Request a current review context and read every bounded chunk of its complete
review document. Check requirements, acceptance, the complete main/epic diff,
task results, independent verification and known limitations. Do not approve a
clipped or stale context. The service records actual reads, not a claimed flag.

Submit APPROVED only for the exact current context with all registered criteria
verified and actual independent tests passed. Submit CHANGES_REQUESTED with
numbered concrete findings, requested changes and registered acceptance text.
A known failed check can support rejection; an unknown test result cannot.
Never substitute a role, test command, scope, spec, owner or tests-passed claim.

For correction use only the configured template identifiers. The service creates
real User-assigned tasks, preserves all earlier deliveries, records a new effective
plan and returns the feedback to the same registered Integration session.
Integration schedules and reviews the correction; do not implement or merge tasks.
Unknown create or dispatch outcomes require reconciliation with the same intent,
not another task, key, Integration session or unverified report.

Wait for the new aggregate handoff and review the updated code and task list.
Keep the epic Active through review and correction. This capability does not
grant Epic-to-main merge or continuation; those require the subsequent services.
